# P3: adapter prototype with real frameworks and the real `waypoint.Checker`

This stage asks a narrower question than P2. P2 uses independent drivers to learn what real frameworks do.
P3 feeds public-API observations from real frameworks into the real `waypoint.Checker` (not an isomorphic
re-implementation), to show the checker can be driven by an external adapter and to state which contracts such
an adapter can and cannot observe.

Scope: this is an adapter-checker integration, not an independent re-confirmation of framework semantics. The
observed facts are the external effect-ledger counts and the checkpoint chain. Everything else is either
synthesized (and labelled) or declared unobservable.

## Running the gate

```bash
./p3/gate.sh        # builds the checker if needed, then runs the matrix
echo $?             # 0 = PASS, 1 = FAIL, 2 = missing prerequisite / build error
```

Prerequisites: JDK 17+, and on a fresh checkout Maven plus network (or pre-vendored jars) for
`langgraph4j-core 1.9.5` and `spring-ai-alibaba-graph-core 1.1.2.4-security-fix`. Missing prerequisites produce
an explicit message and exit `2`, not a bare `mvn: command not found`.

Output: `build/p3-report.md` (untracked, regenerated on every run) plus the frameworks' expected
crash-injection stack traces in `p3/classes/p3-runtime.log`. No tracked file is rewritten.

## What the adapter can observe

| Contract | Visibility here | Observation / limit |
|---|---|---|
| C1 (no re-run of completed steps) | reachable | checkpoint chain (`preCompletedKeys`) + external ledger delta |
| C2 (applied count ≤ 1) | reachable | external effect ledger counts, produced by the real framework run |
| C2 (`STEP_STARTED` durable before effect) | unobservable | frameworks do not expose log record indices, so `protocolObservable=false` |
| C5 (consume-once) | partial | counts are real; `executor` labels are synthetic (derived from the count delta); lease semantics unobservable |
| C3 (fork determinism) | unobservable | exported via `RunResult.unobservable` |
| C4 (checkpoint validity) | unobservable | no log-prefix index over checkpoint snapshots |
| S1 (stream prefix / cancellation) | unobservable | no chunk log at the framework layer |
| S2 (compaction provenance) | unobservable | no compaction records |
| C6 / S3 / L1 | not covered | adapter supplies no `replayHashes`, metering or log-integrity observations |

An unobservable contract is declared, not reported as clean. The adapter contract (`unobservable`,
`protocolObservable=false`) makes "could not check it here" a first-class outcome.

## Matrix

The report is generated by `./p3/gate.sh`. 2 frameworks × 4 fault forms = 8 cells, findings computed by the
real checker:

| Framework | Fault | Findings | Detail |
|---|---|---|---|
| langgraph4j | CRASH_AFTER_EFFECT | C2 | `c=2 b=1`, effect `node:c` applied 2× |
| saa-graph | CRASH_AFTER_EFFECT | C2 | `c=2 b=1`, effect `node:c` applied 2× |
| langgraph4j | CRASH_BEFORE_EFFECT | clean | `c=1 b=1` |
| saa-graph | CRASH_BEFORE_EFFECT | clean | `c=1 b=1` |
| langgraph4j | DOUBLE_RESUME_SAME_CP | clean | `c=1 b=1` |
| saa-graph | DOUBLE_RESUME_SAME_CP | clean | `c=1 b=1` |
| langgraph4j | CONCURRENT_RESUME (real threads) | C2+C5 | `c=2–3` (race), `b=1`, `threads-errors=0` |
| saa-graph | CONCURRENT_RESUME (real threads) | C2+C5 | `c=3, b=1`, `threads-errors=0` |

Concurrent cells are genuine thread races and the gate samples them 3 times per run; a single `c` value would
imply a stability that is not there. `c` is 2 or 3 depending on timing:

| Framework | Sample sets observed across gate runs | Observed range | Finding classes across runs | Grade consistent | Thread errors |
|---|---|---|---|---|---|
| langgraph4j | `[3, 2, 3]`, `[2, 3, 3]`, `[2, 2, 2]` | 2–3 | C2+C5 | yes | 0 |
| saa-graph | `[3, 3, 3]` | 3 | C2+C5 | yes | 0 |

A single `c` value is not a result. The gate criterion is the finding grade: C2+C5 on both frameworks, the same
grade across the 3 runs, and zero thread errors. The ledger count itself is timing-dependent.

Gate criterion (all must hold): at least two frameworks produce findings; the concurrent-cell finding grade is
identical across the 3 runs; cumulative thread errors = 0. The gate compares finding classes, not unstable
ledger detail. Latest gate: PASS with `frameworks-with-findings=2`, `concurrent-grade-consistent=true`,
`thread-errors=0`.

## Synthetic observations

- Ledger counts are real framework observations. `ApplyRecord(startedRecordIndex=0,
  syncedFrontierAtApply=1)` is a synthetic placeholder; the C2 ordering assertion is disabled via
  `protocolObservable=false`, so those fields prove nothing.
- Concurrent-cell `executor` labels (`runner`/`resumer1`/`resumer2`) are derived synthetically from the ledger
  count delta, only to let the checker exercise the C5 executor-diversity rule. Lease semantics remain
  unobservable.
- The event stream is synthesized from the observed node set (no `CHECKPOINT`/`CHUNK`/`CANCELLED`/`COMPACTION`
  records), which is why C3/C4/S1/S2 appear in `unobservable`.

## Limitations

1. The adapter does not independently re-confirm the frameworks' semantics; P2 does that with real SIGKILL and
   real concurrent processes.
2. The gate does not show that both concurrent threads re-executed the node. C2/C5 look at the total effect count
   compared with the pre-recovery count; a `c=2` observation cannot distinguish "one resumer ran twice" from
   "two resumers ran once each".
3. C6/S3/L1 are not checked, nor is any framework behaviour that needs log record indices, replay hashes or
   metering evidence.
4. A clean checkout without Maven or network cannot reproduce the matrix (framework jars are git-ignored; see
   `p2/lab/README.md`).
