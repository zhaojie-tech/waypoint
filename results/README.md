# results/: committed reproducibility evidence

These files are generated. Do not hand-edit them.

| File | Generated by | Purpose |
|---|---|---|
| `gate.txt` | `./scripts/update-results.sh` | Human-readable output of the last successful `./gate.sh` run |
| `gate.json` | `./scripts/update-results.sh` | Canonical copy of `build/gate-result.json` (frozen schema, sorted keys) |
| `p3-conformance.md` | `./scripts/update-results.sh` (when `build/p3-report.md` exists) | Dated P3 conformance snapshot from a local run. CI refreshes only `gate.txt`/`gate.json`; the P3 concurrency ledger values are race-dependent, so this snapshot is evidence of one run, not a CI-enforced invariant. |
| `s1-matrix.md` | `./scripts/update-results.sh` (when `build/s1-matrix.md` exists) | Dated P4 S1/S2 matrix snapshot from a local run (not refreshed by CI). |

The headline numbers in the README are claims, so the gate output is committed. CI runs `./gate.sh`, refreshes
these files with `./scripts/update-results.sh`, and then runs `git diff --exit-code results/`. If the gate's
numbers change, the PR has to update `results/` and the README marker blocks together, so reviewers see the
change.

```bash
./scripts/update-results.sh          # run gate, refresh results/
./scripts/update-results.sh --skip-gate   # reuse build/gate-result.json
```

`build/gate-result.json` is ignored by git; only the canonical copy under `results/` is committed. The `jdk` field
records the runtime that produced the numbers. The CI workflow runs the gate on JDK 17 and 21 for compatibility,
but refreshes `results/gate.*` on JDK 17 only. At v0.1.0 the workflow has not run publicly yet.

Snapshot provenance: `p3-conformance.md` and `s1-matrix.md` were recorded on 2026-10-19 from the v0.1.0 tree by a
local run. They are dated evidence of one run (the P3 concurrency count is race-dependent), not a CI-enforced
invariant.
